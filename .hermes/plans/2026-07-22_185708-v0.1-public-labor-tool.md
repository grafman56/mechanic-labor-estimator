# Mechanic Labor Planner v0.1 Implementation Plan

> **For Hermes:** Implement this plan task-by-task using test-first changes.

**Goal:** Turn the feasibility prototype into a useful static public labor-planning tool with searchable job templates, shareable estimates, and clear estimate boundaries.

**Architecture:** Keep the site as plain HTML/CSS/browser JavaScript. Store generic job templates in `src/estimator.js`; keep calculations pure and unit-tested. The browser UI reads URL state only for a selected job and labor rate, so an estimate can be shared without a backend.

**Tech Stack:** HTML, CSS, ES modules, Node's built-in test runner.

---

## Current context and assumptions

- Source repo: `paul/mechanic-labor-estimator`; working branch: `hermes/feasibility-prototype`.
- The prototype already has eight generic templates and does not claim vehicle-specific fitment, labor-guide data, live prices, diagnosis, or final quotes.
- LEMON/CHARM may inform later manual research. This version must not scrape, copy, or republish their content.
- Hostinger deployment remains a direct static-file upload.

## Final verification

1. Start `python3 -m http.server 8080 --bind 127.0.0.1` from the repository.
2. Confirm `curl -f http://127.0.0.1:8080/` returns the page.
3. Verify a URL such as `?job=brake-pads-rotors&rate=150` loads the correct estimate, then test copy-link and a no-results search in a browser.
4. Stop the server.
5. Push the focused branch to Forgejo only and provide its compare URL.

## Risks and deliberate exclusions

- Generic labor ranges are useful for planning but cannot be represented as flat-rate times for every vehicle.
- No VIN decoding, fitment, manual extraction, or live RockAuto prices are in scope. Those require a permitted, vehicle-specific data strategy.
- No backend means no saved customer records, authentication, analytics, or server-side pricing.
